# 図面解析結果を既存設計へ取り込む

ユーザーの「元アプリの設計データとして扱う」「じゃあそうして」に基づく変更。

1. 目的: 解析結果を既存の案件・ユニット・設計部材へ変換し、構成ツリー、既存の正面・3D、材料構成、木取り、保存から利用する。
2. 入力: 位置付き部材JSON。任意の `design` に外寸、3寸法のXYZ方向、枚数分の配置式と出典を持つ。画像のピクセルから寸法・位置を確定しない。
3. 出力: 元アプリの `units[].structure.customParts` と `structure.parts`。同一元図面は1ユニット。読取根拠は各部材の `drawingSource` に保持する。
4. データ: `drawingLayout` は元図面ID・製作台数・外寸の出典を保持する。取込部材は長さ・幅・厚みの式、XYZ方向、配置インスタンス、元の寸法・枚数・仕上げ・接合メモを保持する。
5. 自動計算: 確定済み値は独立して取り込む。未確定値・参考値は式／図面表記のまま残し、0や18mmで補完しない。外寸未設定時の表示範囲はW/H/Dの確定値として式に使わず、手入力で成立した軸だけ使用する。3寸法・方向・位置が成立するインスタンスだけを3Dと正面に表示する。既存の自動箱は追加しない。数量は1台分×製作台数。
6. 手動変更: 既存の部材編集で名称・3寸法・数量・材料構成を変更する。取込部材には方向・各枚のXYZ位置式とメモも表示する。元図面の読取値とは区別する。図面と設計画面を相互に開ける。
7. 既存への影響: 既存の追加部材・材料構成・木取り経路を使用する。取込モードだけ自動箱と区画生成を使用しない。旧ユニットの動作は維持する。
8. 保存互換: 追加項目がない旧案件は従来どおり。再取込は保存済みの設計編集を上書きしない。JSON保存・再読込・案件木取りの縮約スナップショットに追加項目を保持する。
9. Undo/Redo: 取込部材の寸法・位置・方向・数量・メモを戻せる。履歴は案件IDとユニットIDの組で分離し、同じ元図面を別案件へ取り込んでも混在させない。履歴はセッション内、保存した値と読取根拠は再読込後も保持する。
10. エラー: 寸法未確定、配置不足、方向未設定、材料構成未設定、構成厚と設計厚の不一致を表示する。木取りで未成立の部材を切断片へ展開せず、未展開部材を理由付きで報告する。数量は有限な1〜1000000の整数のみ許可し、配置欄は先頭100枚まで表示する。保存済みの全配置・枚数は保持する。
11. テスト: コアで旧案件維持・数量・未確定・位置式・再取込を検証。実ブラウザーで既存ツリー、3D、既存材料選択、木取り、再読込、Undo/Redo、図面との相互移動を検証。実図面はローカルのみ。

矩形の既存3Dプレビューを使用する。曲線加工・切欠き・加工表の自動展開は元図面のメモを保持し、矩形形状から加工を推測しない。
